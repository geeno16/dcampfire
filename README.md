# Костёр / Digital Campfire

Android-приложение для общения в небольших кострах. В архиве находятся исходники Android (Kotlin, Jetpack Compose), сервер (FastAPI, PostgreSQL), локальная конфигурация Docker и собранный отладочный APK. Интерфейс русскоязычный; аккаунты, костры, приглашения и сообщения хранятся на вашем компьютере.

## Запуск сервера

Нужны Docker Desktop или Docker Engine с Compose v2. В корне проекта выполните:

```bash
python3 scripts/setup_local.py
docker compose up -d --build --wait
```

На Windows вместо `python3` обычно используется `py`. Скрипт создаёт `.env` с уникальными секретами при первом запуске и сохраняет существующий файл при повторном. API будет доступен на [http://localhost:8001/docs](http://localhost:8001/docs), а письма с кодами появятся в [Mailpit](http://localhost:8025). Почта наружу не отправляется. При ошибке запуска проверьте `docker compose logs app-prod db mailpit`.

Для остановки: `docker compose down`. Данные аккаунтов и аватары сохраняются в томах Docker и остаются после остановки. Команда с `-v` удалит их без восстановления; для обычной остановки она не нужна.

## Android Studio и устройство

Откройте папку `android` как проект. Установите Android SDK Platform **37.0** и Build Tools **36.0.0** через SDK Manager, используйте JDK **21** для Gradle. Первая сборка загружает Gradle и зависимости. Затем выберите эмулятор с Android 8.0+ и нажмите Run либо выполните:

```bash
cd android
./gradlew :app:assembleDebug
```

На Windows используйте `gradlew.bat`. APK появится в `android/app/build/outputs/apk/debug/app-debug.apk`; готовая копия также лежит в каталоге `release` итогового архива. Эмулятор обращается к серверу через `10.0.2.2:8001` автоматически.

Для физического устройства включите отладку по USB и выполните `adb reverse tcp:8001 tcp:8001`, затем установите отладочный APK. Приложение использует `localhost:8001`; телефон должен оставаться подключён к компьютеру по USB. Команда `./gradlew :app:adbReverse` настраивает перенаправление для подключённых устройств. На сервере должен работать Docker.

Готовый APK подписан отдельным отладочным ключом сборки. Если Android Studio позже соберёт приложение с другим ключом и обновление не установится, удалите старую отладочную версию с устройства и установите новую. Локальный кеш приложения при удалении очистится, данные сервера останутся.

Если обновляете установленную версию **0.1.0**, откройте `android` из нового архива и выполните в терминале Android Studio (PowerShell):

```powershell
.\gradlew.bat :app:adbReverse
.\gradlew.bat :app:installDebug
```

Уже запущенный Docker и аккаунт сохраняются. После установки откройте «Костёр» и обновите список на главном экране.

В приложении зарегистрируйтесь, откройте письмо с шестизначным кодом в Mailpit, подтвердите почту, выберите темы и создайте костёр. Для проверки приглашений и чата нужен второй аккаунт (например, на другом эмуляторе). Отключив сеть после загрузки данных, можно проверить сохранённые костры и сообщение об отсутствии связи.

## Проверки и устройство проекта

Серверные тесты запускаются в отдельной временной базе, не затрагивая пользовательские данные:

```bash
docker compose --profile test run --build --rm test
```

Тесты Android API: `cd android && ./gradlew :api:test`. Проверки оформления Kotlin и Android: `./gradlew spotlessCheck :app:lintDebug :app:detekt`. Подробное сопоставление с исходными требованиями — в [REQUIREMENTS.md](REQUIREMENTS.md).

Проверки уже выполненной сборки и ограничения испытаний указаны в [RELEASE_NOTES.md](RELEASE_NOTES.md). Исходные Word/PDF, схемы и предыдущие версии проекта находятся в папке `original` итогового ZIP.

Каталоги: `backend/src` — API, правила и WebSocket; `backend/test` — тесты; `android/api` — клиент и код, генерируемый из `android/api/openapi.json`; `android/app` — интерфейс и шифрованный локальный кеш. Контракт обновляется командой `cd backend && python export_openapi.py`, затем пересобирается клиент. Сервер при старте создаёт таблицы и начальный каталог тем в уже существующей базе PostgreSQL.

## Границы локального запуска

Письма принимает локальный Mailpit, а HTTP разрешён в отладочном APK только для адресов локальной разработки. Это сборка для разработки и испытаний. Размещение сервера, российский адрес хранения персональных данных, реальная почта, TLS, публичная политика обработки данных и измерение задержек на устройствах и сети требуют отдельной инфраструктуры и испытаний. Публикация такой конфигурации в интернет не предусмотрена.
